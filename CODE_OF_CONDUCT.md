# Code of Conduct

## Our Commitment

Workflow OS is a collaborative project, and we want contributions, discussions, issues, and code reviews to remain respectful, constructive, and professional.

We welcome contributors regardless of their background, experience level, technical ability, nationality, gender, religion, or any other personal characteristic.

## Expected Behavior

Participants are expected to:

* Be respectful and professional in discussions and code reviews.
* Provide constructive feedback focused on the work, not the person.
* Explain technical disagreements in good faith.
* Welcome different approaches and perspectives.
* Give appropriate credit to contributors and existing work.
* Keep discussions relevant to the project.
* Respect the privacy and personal information of other contributors.
* Report security issues responsibly rather than publicly exposing vulnerabilities.

## Unacceptable Behavior

The following behavior is not acceptable:

* Harassment, discrimination, intimidation, or personal attacks.
* Trolling, deliberately disruptive behavior, or repeated bad-faith arguments.
* Offensive or inappropriate language directed at individuals or groups.
* Publishing someone's private information without permission.
* Threats of violence or encouraging harm.
* Deliberately submitting malicious code, credentials, malware, or other harmful content.
* Misrepresenting another person's work or contribution.
* Any behavior that would reasonably be considered inappropriate in a professional development environment.

## Project Spaces

This Code of Conduct applies to all Workflow OS project spaces, including:

* GitHub issues
* Pull requests
* Discussions
* Code reviews
* Commit messages and repository contributions
* Project-related communication channels
* Public spaces when someone is officially representing Workflow OS

## Contribution Standards

Contributors should make a reasonable effort to:

* Keep pull requests focused and understandable.
* Clearly describe significant changes.
* Avoid committing secrets, API keys, credentials, or private information.
* Test changes where practical before submitting them.
* Respect existing project architecture and conventions.
* Document meaningful changes that affect users, deployment, security, or system behavior.

## Enforcement

Project maintainers are responsible for maintaining a respectful and productive project environment.

Depending on the circumstances, maintainers may:

1. Ask a participant to modify or stop inappropriate behavior.
2. Remove inappropriate comments, issues, commits, or other contributions.
3. Temporarily restrict participation in project spaces.
4. Permanently restrict participation in serious or repeated cases.

Enforcement decisions will be made based on the circumstances and the interests of the project community.

## Reporting

If you experience or witness behavior that violates this Code of Conduct, report it privately to the project maintainers through the repository's available contact or communication channels.

Please avoid publicly posting sensitive personal information or security-related details when reporting an issue.

Reports will be handled as confidentially as reasonably possible.

## Security Concerns

Security vulnerabilities should not be disclosed through public issues.

If you discover a vulnerability involving authentication, credentials, secrets, workflow execution, blockchain verification, database access, or another security-sensitive component, report it privately to the project maintainers so it can be investigated responsibly.
